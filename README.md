# センチメンタル・ハナエ

選択肢を選んで進める恋愛ADV。文化祭実行委員として出会った味村ハナエへの告白に成功すればクリア。

**遊ぶ: https://purplegames-creator.github.io/purple-hanae/**

- 全23イベント(固定20 + 自由行動プール6から3つ選択)＋隠しライバル「吉沢」による特殊分岐
- 好感度は非公開。ハートの演出(数・大きさ・動き)と、ハナエの反応だけが手がかり
- 背景7種・立ち絵2種(夏服/冬服)。パーフェクト達成時だけ季節が進んだ専用エピローグに入る
- エンディング7種(成立2 / 不成立4 / 最下位「四十一歳の似顔絵」)。localStorage によるセーブ・中断・再開に対応
- 本文は**1ブロックずつ表示し、タップで送る**(1ブロック最長52字、1イベント平均4.3ブロック)。パネルの高さは固定で、文章量では動かない。**読み終えてもう一度タップするまで選択肢は出さない**
- 読み飛ばした本文は HUD の「これまで」から読み返せる(選択の取り消しはできない)
- BGM 12曲(場面ごとに切り替え)。文字送りに合わせて音が鳴り、ハナエのセリフだけ音程が高い

## 遊び方

`index.html` をブラウザで開くだけで動作します(ビルド不要、素のHTML/CSS/JS)。

## 構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面構造。ここが公開ファイル |
| `style.css` | スタイル・背景レイヤー・立ち絵・ハート演出 |
| `game-data.js` | 全イベントのテキスト・選択肢・点数・演出データ |
| `game.js` | ゲーム進行エンジン |
| `audio.js` | BGM の切り替えと、Web Audio で合成する効果音 |
| `assets/` | 背景7点・立ち絵12点(基本2 + 表情差分10)・タイトルロゴ・OGP画像 |
| `assets/bgm/` | BGM 12曲(m4a)。元ファイルと変換手順は `_source/bgm/README.md` |

キャッシュバスター `?v=NN` の正は **`index.html` の1箇所だけ**。`game.js`(画像)と `audio.js`(BGM)は
自分の `<script src>` の `?v=` を読んで同じ数字を使うので、JS/CSS/画像/BGM のどれを更新しても
`index.html` の `?v=` を全部 bump すればよい。

HUD の日付は `game-data.js` の `dates` / `freeDates` / `dateLabels`。準備は夏休み中の登校作業(7/20〜8/7)、
本番は夏休み明け(9/5-6)。イベントを足したらここにも日付を入れる(無いと HUD が空になる)。

## 本文の書き方

- 段落は `

`。「」の中はセリフ、外は地の文。1つの枠に混ぜない(自動で割る)
- セリフの話者は既定でハナエ。**他の人のセリフは行頭に `俺「〜」` `委員「〜」` `吉沢「〜」` `トウマ「〜」` `山崎「〜」` のように名前を付ける**(名前は名札に出て、本文には残らない)。古い本文は `game.js` の `SPEAKER_BY_LINE` で名指ししてある
- 地の文の中で括弧を使いたい時(貼り紙の文字など)は `『』` を使う(`「」` はセリフとして割られる)
- 反応は「ハナエの返し」だけ。採点を言葉で言わない(「悪くない反応」のような地の文は書かない)。一拍の仕草を足す時は `

` で2つ目の枠に
- 1文は 50字以内に(枠は3〜4行で固定。長い段落は文で割られるが、1文が長いと割れない)
- 結末の途中で場面を変えるには `endings.<key>.sceneChanges: [{ marker: "その枠の先頭の文字列", scene: {...} }]`。一枚絵は `scene.cg`(`assets/<名前>.webp`。無ければ出ない)

## 画面のレイアウト

- **1000px 以上**(PC・iPad 横): ADV の定石配置。本文窓を画面下に敷き、選択肢はその上の左側、立ち絵は右、HUD は上端に固定。反応中は本文窓が反応窓に置き換わる
- **1000px 未満**(スマホ・iPad 縦): 立ち絵を上端基準・画面の高さの 56% で**中央**に立たせ、本文と選択肢は下 68% までを使う。あごは上から約 22% に来るので顔は隠れない(実測の余白 23〜346px)。足元はパネルの後ろに隠れ、境目が硬くならないよう下端をフェード(`mask-image`)
- **横向き(高さ 560px 以下)**: 縦に積むと必ず顔に枠が掛かるので、**左に文章・右に立ち絵**の横並びにする。文章の列は 62vw
- 本文枠は2層。外側 `.textbox` が箱と**名札**(`data-speaker` を CSS の `::before` で表示。ハナエ=ピンク / 主人公=紫 / その他=灰)、内側 `.event-text` が固定高さのスクロール領域。名札は枠の上に 13px はみ出すので、狭い画面のスクロール領域には `padding-top: 16px` が要る
- 音の設定は ♪ ボタンのパネルから(音楽 / 効果音のスライダー + 消音。`localStorage` に保存)

## 難易度設計

バランスはモンテカルロで検証している(`SUCCESS_THRESHOLD=76` / `FRIEND_THRESHOLD=52` はその結果。2026-09-04 に 68/38 から引き上げ)。

| プレイヤーモデル | 成功 | パーフェクト | 友達 | 不成立(うち似顔絵) | 吉沢 |
|---|---|---|---|---|---|
| 一様ランダム(4択を等確率で選ぶ) | 3% | 0% | 60% | 26%(8%) | 11% |
| ふつうのプレイヤー(6割は失礼・消極的を避ける) | 71% | 1% | 25% | 0% | 2% |
| 失礼・消極的な選択肢を避ける初回プレイヤー | 96% | 4% | 0% | 0% | 0% |

**イベントの追加や点数の変更をしたら、必ず `SAVE_VERSION` を上げて再計測すること。**
上げ忘れると、古いセーブが新しい進行キューと噛み合わずに壊れる。

## 立ち絵の表情差分を追加する

立ち絵は**背景透過の全身像**(566x1000)。広い画面は右に等身大、狭い画面は中央に 56dvh。
狭い画面では**立ち絵の位置を画面の上端から決める**(下端から決めると、画面が低い機種ほど
顔が下がってパネルに潜り込む)。上端基準なら、画面の高さが変わっても顔は必ず上 26% に収まる。

**表情は選択肢ごとに `game-data.js` の `expr` で指定済み**(全103選択肢)。
点数から自動で決めると本文と2割ずれるため、リアクション本文を読んで1件ずつ割り当ててある。

以下のファイル名で `assets/` に置き、**`game.js` の `SPRITE_EXPRESSIONS` にも足す**と使われる。
リストに無い表情は、リクエストを投げる前に `hanae_<outfit>.webp` へ落ちる(冬服は `soft` しか
無いので、夏服向けの表情がそのまま渡ると毎回404を踏むことになる。それを防ぐための一覧)。

| ファイル名 | 表情 | 出番 |
|---|---|---|
| `hanae_summer.webp` | 普通の笑顔(提供済み・ベース) | 11回 |
| `hanae_summer_normal.webp` | 真顔〜わずかな微笑み | 21回 |
| `hanae_summer_soft.webp` | 静かに心を許した顔。笑っていないが柔らかい | 17回 |
| `hanae_summer_trouble.webp` | 困り顔・苦笑い | 16回 |
| `hanae_summer_lonely.webp` | 寂しげ。笑っていない、視線が落ちる | 12回 |
| `hanae_summer_angry.webp` | ムッとした顔。怒鳴ってはいない | 10回 |
| `hanae_summer_surprise.webp` | 目を見開いた驚き | 6回 |
| `hanae_summer_shy.webp` | 照れ。頬に赤み、目を逸らす | 6回 |
| `hanae_summer_joy.webp` | 満面の笑み | 3回 |
| `hanae_summer_cry.webp` | 泣きそう。目が潤む | 1回 |

冬服は `hanae_winter_soft.webp` の1枚だけあればよい(パーフェクトエピローグ専用)。

タイトルロゴは `assets/logo_title.webp`(960x463・透過)。元データは `_source/logo_title_*.png`。

場面の入りの表情は `game-data.js` の `scenes` / `endingScenes` の `expr` で指定する。

**立ち絵は場面の入りでは出さない。** ハナエが最初に口を開いたブロック(話者が彼女 = `voice 1`。
E1 の「？？？」も含む)で、ふわっと現れる。本文で一度も喋らない場面(E16 など)は、
選択後の反応で初めて出る。仕組みは `game.js` の `pendingSprite` / `revealSpriteFor()` で、
`applyScene(scene, true)` を呼んだ画面(本編・告白)だけが対象。エンディングは最初から出す。

## 音

BGM は **DOVA-SYNDROME** (https://dova-s.jp/)。12曲を場面ごとに張り替える。
全曲 -16 LUFS に揃えてあるので、場面が変わっても音量は跳ねない。曲ごとの音量差は
`audio.js` の `TRACKS` で意図的に付けている(静かな場面だけ小さい)。

**BGM は「かすかに聞こえる」くらいまで絞ってある。** 主役は文字送りの音とハナエの反応で、
曲はその下に敷くもの。全体の音量は `audio.js` の `BGM_MASTER` 1箇所で上下できる
(現在 0.3。実効レベルは title で -33.5dBFS = 文字送りの音の 19dB 下。0.07 だった時期は
iOS の音量バグを前提に下げた値が残っていたもので、事実上無音だった)。

> **iOS Safari は `HTMLMediaElement.volume` を無視する**(音量はハードのボタン専用という
> Apple の仕様)。そのため `<audio>` を Web Audio の GainNode に通して音量を決めている。
> **`el.volume` に戻すと iPhone だけ音量指定が効かなくなる**ので、触らないこと。
> 併せて `navigator.audioSession.type = playback` を立てている。これが無いと本体側面の
> サイレントスイッチで Web Audio(文字送りの音)だけが消える。

**場面と曲の対応は `game.js` の `BGM_BY_KEY` 1箇所**。1周でエンディング以外の8曲すべてを
使い、切り替えは13回。場面を足してここに書き忘れても、無音にはならず `daily1` に落ちる。

| 曲 | 場面 |
|---|---|
| `title` | タイトル・プロローグ |
| `daily1`〜`daily5` | 日常イベント。**1周の中で5曲すべて使う**。幕が進むごとに切り替えて、同じ準備期間でも時間が動いている感じを出す |
| `quiet1` | 夏の、まだ距離がある静けさ(E5/E8/E12/E13)と、最後の夜(E19) |
| `quiet2` | 本音が出る終盤(E14/E14B)と告白。「気持ちを伝える」を押した瞬間に曲を止め、無音を一拍置く |
| `tension` | トラブル・吉沢・噂 |
| `end_true` / `end_false` / `end_rival` | エンディング |

効果音は**ファイルを持たない**。`audio.js` が Web Audio で合成する。
「画面をタップ」でゲームが始まる時は `start`(C5→G5→C6 を 110ms ずつずらして重ねる sine の分散和音)。
**解錠の瞬間はまだ AudioContext が起きていないことがある**ので、`AUDIO.seWhenReady()` で
running になってから鳴らす(`ctx.onstatechange` か 400ms の保険タイマー)。文字送りの音は
話者で音程を変えていて、ハナエが一番高い(`VOICES` の 0=地の文 / 1=ハナエ /
2=他の登場人物 / 3=主人公)。

話者の見分けは「」の中かどうかで決め、**ハナエ以外のセリフだけ `game.js` の
`LINES_OTHER` / `LINES_HERO` に名指し**してある(全59セリフを目視して確定させた)。
本文を書き換えるとリストから外れてハナエの声になるだけで、壊れはしない。

タイトルの「画面をタップ」は、ブラウザが最初のタップより前に音を出させないための門。
**1回のタップで解錠と曲の再生が同時に始まる**(`pointerdown` で解錠、同じタップの `click` で門が開く)。
立ち上がりは `UNLOCK_FADE_MS`(800ms)と `UNLOCK_RISE_POW`(1.3)。ここを長く/急にすると
「タップしても鳴らない」と感じられるので注意(2200ms + t² の頃は 1秒経っても目標の 21% で無音同然だった)。

実機で音が出ない時は `AUDIO.state()` をコンソールで叩くと、どこで詰まっているか分かる。
